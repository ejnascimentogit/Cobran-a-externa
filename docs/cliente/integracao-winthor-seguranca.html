Integração segura com o WinThor

Cobrança Externa · leitura de títulos vencidos
Versão para o cliente

O que a integração faz

A Cobrança Externa lê do seu WinThor apenas os títulos vencidos em aberto, na faixa de atraso que você definir (por exemplo, de 30 a 180 dias), e os dados de contato do cliente devedor (nome, endereço, telefone, praça e rota), para montar as rotas de cobrança presencial. Depois, confere diariamente quais títulos foram pagos. Nada é gravado ou alterado no seu ERP.

Como os dados trafegam

O que pedimos ao cliente

  • Um servidor ligado o tempo todo, com acesso ao Oracle na rede local.
  • Um responsável da TI para autorizar a instalação e criar o usuário de leitura.
  • Resultado das consultas de verificação (passo 3).

Passo a passo (por cliente)

  1. Autorizar a instalação. Liberar a instalação de um serviço e a saída HTTPS (porta 443). Não é preciso abrir nenhuma porta de entrada.
    TI do cliente
  2. Usuário de leitura no Oracle. Criar um usuário apenas com permissão de leitura (SELECT) nas tabelas de títulos e clientes necessárias. A lista exata é combinada na implantação.
    TI do cliente
  3. Consultas de verificação. Rodar as consultas de conferência de colunas (coordenadas, praça e rota) e enviar o resultado ao analista do EFR.
    Analista do EFR
  4. Criar o túnel. Um túnel exclusivo para o cliente, com endereço próprio, no Cloudflare Zero Trust.
    Equipe EFR
  5. Instalar no servidor. Instalar o cloudflared (com o token do túnel) e a API de leitura, em um servidor que fique ligado e alcance o Oracle.
    TI + Analista EFR
  6. Proteger o acesso. Criar a regra do Cloudflare Access com token de serviço, para que só o sistema da Cobrança Externa chame o endereço.
    Equipe EFR
  7. Ativar a sincronização. Guardar endereço e token de forma segura e ligar a rotina diária. Teste final: uma consulta pelo túnel e uma sincronização completa.
    Equipe EFR

Segurança

Acesso ao ERP
  • Usuário Oracle somente leitura, só nas tabelas combinadas
  • Consultas padrão, com parâmetros (ex.: faixa de dias em atraso)
  • Limite de volume por consulta e de consultas por minuto
Acesso ao túnel
  • Token de serviço com validade, renovado periodicamente
  • Segunda trava: assinatura com data e hora em cada pedido
  • A API só aceita pedidos que chegam pelo túnel
Dados
  • Só títulos vencidos em aberto e dados do devedor
  • Cada empresa vê apenas os próprios dados
  • Registros (logs) sem dados pessoais
Controle do cliente
  • Pode parar o serviço a qualquer momento
  • Pode revogar o token e desativar o usuário Oracle
  • Credenciais do Oracle ficam somente no servidor do cliente

Pontos de atenção

  • O Cloudflare, como intermediário confiável, processa o tráfego ao terminar a criptografia. Se o cliente exigir sigilo inclusive diante do Cloudflare, é possível cifrar o conteúdo com uma chave exclusiva (sob consulta).
  • Quem tiver o token do túnel ou o token de serviço pode usá-lo; por isso a validade definida, a renovação e a assinatura em cada pedido.
  • A guarda e o prazo de retenção dos dados seguem acordo de tratamento de dados (LGPD) firmado com o cliente.
